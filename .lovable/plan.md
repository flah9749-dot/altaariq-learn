تم بالفعل حذف "الأرشيف" و"مكتبة الخرائط" من القائمة الجانبية (الصفحات نفسها لم تُحذف حتى لا يتعطل كود يعمل).

في ما يلي خطة تنفيذ نظام الذكاء الاصطناعي الجديد. حجم العمل كبير جداً، لذلك قسّمته إلى 5 مراحل — ننفذ مرحلة ثم تراجعها ونكمل.

## المرحلة 1 — طبقة المزوّد (AI Provider Layer)
- واجهة موحّدة `AiProvider` بصيغة OpenAI-compatible: تدعم OpenRouter (افتراضي) وTogether وOllama وأي endpoint متوافق، بالإضافة إلى Lovable AI كاحتياطي.
- جدول `ai_provider_config`: المزوّد، الـ base URL، اسم النموذج، تفعيل/تعطيل، ترتيب الاحتياطي. مفتاح الـ API يُخزَّن كـ Secret على الخادم (لا يُعرض للواجهة).
- النموذج الافتراضي: أحدث Qwen Instruct مستقر على OpenRouter.
- تعديل `src/lib/ai/router.server.ts` ليقرأ الإعدادات من قاعدة البيانات بدل القوائم الثابتة — بدون تغيير توقيع `callAI` حتى لا تتأثر أي صفحة.
- في `/admin/ai`: تغيير المزوّد/النموذج/المفتاح + زر "اختبار الاتصال" + سجلّات.

## المرحلة 2 — قاعدة المعرفة (Knowledge Base + pgvector)
- تفعيل `pgvector` وجداول: `kb_documents` (الملف، النوع، الصف، المادة، حالة المعالجة) و`kb_chunks` (النص، الوحدة، الدرس، الصفحة، embedding) مع فهرس HNSW وسياسات RLS + GRANT.
- Pipeline تلقائي بعد الرفع: استخراج النص (PDF/Word/صور OCR) ← اكتشاف الفهرس/الوحدات/الدروس ← تقسيم ذكي ← Embeddings ← تخزين.
- استراتيجية تقسيم مختلفة لكل نوع مستند: كتاب وزارة (وحدات/دروس)، بنك أسئلة (لكل سؤال)، مراجعة (عناوين)، امتحانات (لكل امتحان)، مذكرة (عناوين + صفحات).
- المعالجة تتم على دفعات في الخلفية مع متابعة الحالة (قيد المعالجة/تم/فشل) وإعادة الفهرسة والحذف.
- في صفحة رفع الملفات: حقل "طريقة معالجة المستند" + الصف الدراسي.

## المرحلة 3 — البحث الذكي RAG
- ترتيب التنفيذ في كل طلب: كاش ← بحث دلالي في قاعدة المعرفة (مقيّد بصف الطالب تلقائياً) ← إن كفت المقاطع يُبنى الرد منها ← وإلا يُستدعى النموذج مع المقاطع فقط (لا يُرسل الكتاب كاملاً).
- صف الطالب يُقرأ من ملفه — لا يُسأل عنه أبداً؛ ويمكن توسيع البحث مؤقتاً لطلب صريح ثم العودة تلقائياً.
- كل إجابة تعرض مصدرها: الصف / الوحدة / الدرس / الصفحة / اسم الملف.
- ملفات الطالب المرفوعة: استخراج النص ← دمجه مع مقاطع المنهج ← الشرح.
- الكاش يشمل التشابه الدلالي للأسئلة المتقاربة لتقليل الاستدعاءات.

## المرحلة 4 — تجربة الشرح والامتحانات
- برومبت "مدرس دراسات اجتماعية" مضبوط حسب المرحلة الدراسية، إجابات مرتبة ومختصرة ومستندة للمحتوى.
- أزرار بعد كل إجابة: أبسط / بالتفصيل / كأنني طفل / تلخيص / خريطة ذهنية / جدول مقارنة / خط زمني / أسئلة تدريبية / امتحان.
- توليد الامتحانات: يجمع محتوى الدرس/الوحدة من قاعدة المعرفة أولاً ثم يولّد منه فقط، مع دعم توليد من PDF مرفوع مباشرة، واختيار العدد والصعوبة والنوع والدرجة والزمن.

## المرحلة 5 — "اسأل المدرس" + لوحة الإدارة
- عند ضعف الثقة: لا يخترع إجابة — يُحفظ السؤال في جدول `teacher_questions` ويُبلَّغ الطالب.
- المدرس يجيب من لوحة الإدارة، وتُضاف الإجابة لقاعدة المعرفة لتُستخدم تلقائياً لاحقاً.
- لوحة `/admin/ai` النهائية: الملفات (رفع/حذف/إعادة فهرسة/الحالة)، الاستخدام والتكلفة، إدارة الكاش، إعدادات المزوّد والنموذج، اختبار الاتصال، السجلات.

## تفاصيل تقنية
- كل شيء يمر عبر `createServerFn` — لا مفاتيح على العميل.
- Embeddings عبر Lovable AI Gateway (`/v1/embeddings`) لتفادي مفتاح إضافي، ويمكن تبديلها لاحقاً من نفس طبقة المزوّد.
- إعادة استخدام `ai_cache` و`ai_usage_logs` والحصص (quotas) الموجودة كما هي.
- لا تغيير في شكل الواجهات الحالية سوى الإضافات المذكورة (حقل نوع المستند، أزرار ما بعد الإجابة، بطاقة المصدر).
