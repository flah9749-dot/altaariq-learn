# اختبار ضغط 5000 طالب متزامن

سيناريو `exam-5k-stress.js` يحاكي الرحلة الحقيقية للطالب (دخول → بدء → حفظ إجابات Batch → تسليم) مع تركيز خاص على قياس **زمن التسليم (submit)** و**حمل قاعدة البيانات**.

## 1) تجهيز البيانات

```bash
# 1. أنشئ 5000 حساب طالب تجريبي في قاعدة البيانات (عبر لوحة الأدمن أو SQL)
# 2. صدّرهم إلى students.json بالشكل:
[
  { "code": "STD-00001", "password": "..." },
  { "code": "STD-00002", "password": "..." }
]
# 3. جهّز امتحاناً منشوراً وانسخ EXAM_ID + قائمة QUESTION_IDS
```

## 2) التشغيل

```bash
k6 run load-tests/exam-5k-stress.js \
  --env ANON_KEY="<anon-key>" \
  --env EXAM_ID="<exam-uuid>" \
  --env QUESTION_IDS="q1,q2,q3,q4,q5" \
  --env DB_PROBE=1
```

خيارات:
- `--env PEAK_VUS=5000` — عدد الطلاب في الذروة (افتراضي 5000)
- `--env PEAK_DURATION=10m` — مدة الذروة
- `--env DB_PROBE=1` — تفعيل استعلام قراءة خفيف لقياس زمن DB مستقلاً

## 3) ماذا يقيس؟

| المقياس | المعنى | الحد المقبول |
|---|---|---|
| `submit_exam_duration` P95 | زمن رحلة التسليم كاملاً | < 3s |
| `submit_exam_duration` P99 | الحالات الأسوأ | < 6s |
| `submit_success` | نسبة التسليمات الناجحة | > 98% |
| `submit_db_write_duration` | زمن انتظار DB وحده (TTFB) | مؤشر حمل PostgREST |
| `db_probe_duration` | زمن قراءة خفيفة | مؤشر حمل DB القاعدي |
| `rate_limited_429` | نسبة الردود 429 | < 1% |
| `server_errors_5xx` | نسبة الردود 5xx | < 0.5% |

## 4) الخطة الزمنية

```
0 → 2m   : 1000 VU     (إحماء)
2 → 5m   : 3000 VU     (تصاعد)
5 → 8m   : 5000 VU     (اقتراب)
8 → 18m  : 5000 VU 🔥  (الذروة الحقيقية - 10 دقائق)
18 → 20m : تهدئة
```

## 5) قراءة النتائج

- الخلاصة تُطبع في stdout وتُحفظ في `summary-5k.txt`.
- التفاصيل الكاملة في `summary-5k.json` (قابلة للاستيراد في Grafana).
- ركّز على **P99 للتسليم** — إذا تجاوز 6s فهناك اختناق في PostgREST أو DB writes.
- إذا ارتفع `db_probe_duration` مع الذروة → الحمل على DB نفسه، ليس فقط على الطبقة الأعلى.
